# mdai-Library v0.1.4 — Hardening

## Ziel

Drei v0.1.3-Folgearbeiten abschließen — reines Hardening, keine Feature- oder
Verhaltensänderung an den Macros (außer dem einen §2-B-Fix). Ein Spec, ein Plan,
drei klar getrennte Task-Gruppen.

## Querschnitts-Constraint: Leanness / DRY

Oberstes Designprinzip dieser Library: **minimaler LOC-/Context-Footprint zur
Laufzeit**. Konkret für diese Arbeit:

- Keine Duplikation von Hard-Rules oder Tool-Nutzungs-Hinweisen — Verweise via
  `@call` / `@include`; einmal in `core/` definiert, vom Skill konsumiert.
- Doku single-sourced: eine kanonische Quelle + Einzeiler-Pointer, statt denselben
  Inhalt in mehreren Dateien zu wiederholen.
- Umsetzung selbst folgt der lean-context-Discipline (`core/lean-context.md`):
  bounded reads, `@call ctx_search` / `ctx_read_lines` statt Voll-Reads.

## Scope

### Task-Gruppe 1 — Engine-Fix-Verifikation & Dependency-Doku

Die Library hängt hart an zwei lokalen markdownai-Engine-Fixes (`f16b4c2`
named-arg-Propagation, `ede9793` `@foreach`-Objekt-Dot-Access). Beide sind auf
`markdownai/feat-mdai` committet, **nicht gepusht** (bewusst, lt. Entscheidung —
kein Push/PR in v0.1.4).

Arbeit:

- **Verifizieren** (kein Code-Change):
  - `git -C markdownai branch --contains f16b4c2` / `… ede9793` → beide auf `feat-mdai`.
  - Zwei Live-Regressions-Smokes gegen den laufenden Dist:
    - **Smoke A (ede9793):** `@foreach` über `@set xs = {{ [{"name":"a"}] }}` →
      `{{ x.name }}` rendert `a` (nicht leer).
    - **Smoke B (f16b4c2):** `call_macro file_check(path={{ var }})` → `file.exists`
      löst den Named-Arg korrekt zu `exists`/`MISSING` auf.
- **Single-source-Doku** (DRY):
  - Kanonisch = `findings-v3` Anhang A. Dort die zwei Repro-Smoke-Kommandos
    **ergänzen**. KEIN separates Smoke-File.
  - `core/mcp-markdownai.md` (Engine-Notes) + Changelog v0.1.4: je **ein
    Einzeiler-Pointer** auf findings-v3 Anhang A („Library benötigt Dist aus
    `feat-mdai` inkl. f16b4c2+ede9793; nach Pull `npm run build --workspaces`;
    verifizieren via Anhang A"). Keine Wiederholung des Inhalts.

### Task-Gruppe 2 — `body.mdai.md:185` `@set`-Pipe-Fix

`@set render_target_resolved = render_target | default("none") /` ist in 1.3.0
ungültig (`"@set" cannot be used as a pipe source`, findings-v3 §2-B).

Arbeit:

- `@set render_target_resolved = … /` **entfernen**.
- Im Prosa-`call_macro`-Pointer den Use-Site umstellen:
  `target="{{ render_target_resolved }}"` → `target="{{ render_target | default('none') }}"`.
- **Verifikations-/Entscheidungs-Gate:** vorab smoken, ob der `default`-Filter in
  der Interpolation greift.
  - Greift er → Use-Site-Inline wie oben.
  - Greift er NICHT → Fallback: `{{ render_target }}` schlicht inline (leer wenn
    unset) ODER `@if`-basierter Default. Entscheidung im Plan dokumentieren.
- `resolve_phase write-outputs` muss anschließend **warning-frei** rendern (kein
  `@set`-Pipe-Fehler mehr).

### Task-Gruppe 3 — Directive-Indentation-Normalisierung

Alle echten `@`-Directives in Library-Files beginnen auf **Spalte 0**.

Arbeit:

- Repo-weites Inventar: `ctx_search "^\s+@" mdai` → alle eingerückten Directive-Zeilen.
  Aktuell bekannt: `write-spec.md` (genested: Closer, `@case`, `@if`, `@else`,
  Opener). Andere Files bereits Spalte 0.
- De-Indent **nur echte `@`-Directives**. AUSGENOMMEN: `@render-template`-Body-Args
  (`key=value`), Markdown-Listen (`- …`), Prosa, Inline-Code.
- Pro geänderter Datei: `validate` + MCP-Smoke der betroffenen Macros (Verhalten
  unverändert).
- `file-utils.md` ist ausgenommen (wird separat vom Maintainer gepflegt).

## Non-Goals

- Kein Push/PR der Engine-Fixes (nur lokal verifizieren).
- Keine Engine-Code-Änderung.
- Keine funktionalen Macro-Änderungen außer dem §2-B-Fix.
- Der IDE-Markdown-Watcher (re-wrappt/-indentiert committete `.md` autonom) ist ein
  User-Env-Thema — nur als Risiko notiert, nicht in dieser Library „gelöst".

## Verifikations-Strategie

- `npx --prefix markdownai mai validate <file>` pro geänderter Datei, immer aus
  Repo-Root (nie aus `markdownai/`).
- MCP `call_macro` / `resolve_phase` als Laufzeit-Wahrheit (cwd = Repo-Root).
- Bekannte validate-Grenze bei `${MDAI_LIBRARY_ROOT}`-Includes (findings-v3 §7) —
  hier nicht betroffen.
- End-Gate: `body.mdai.md` 5 Phasen rendern ohne neue Fehler (erlaubte agent-time
  `@call`/`@query`-Warnings ausgenommen); Regression `ctx_search "^\s+@" mdai` = 0
  (außer den ausgenommenen Nicht-Directive-Zeilen).

## Annahmen / offene Punkte

- `default`-Filter in Interpolation: Verhalten in 1.3.0 noch zu bestätigen
  (Smoke-Gate in Task-Gruppe 2).
- Engine-Fixes bleiben lokal (kein Remote-Backup) — akzeptiertes Risiko; Mitigation
  ist die Dependency-Doku + reproduzierbare Smokes.
