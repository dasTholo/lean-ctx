## 4. Beobachtbare Drift-Pattern

### Drift-1: mode-Inkonsistenz zwischen ähnlichen ctx_read-Calls

- Call 1: `mode="full"` für Cargo.toml (eine kleine Config-Datei — `map` wäre effizienter)
- Call 2: `mode="map"` für CHANGELOG.md (eine große Datei — korrekt)
- Ohne Library-Abstraktion gibt es keine Konvention, welcher mode für welchen Datei-Typ gilt.
- Resultat: Der Agent wählt frei, was zu inkonsistenten mode-Werten führt.

### Drift-2: Namespace-Mix (lean-ctx vs. jetbrains)

- Für Lese-/Such-Operationen: `mcp__lean-ctx__ctx_*`
- Für Reformat: `mcp__jetbrains__reformat_file`
- Diese Mischung erscheint in jedem Commit-Block, ohne dass ein einheitliches Muster erzwungen wird.
- Risk: In einem längeren Plan könnte der reformat-Schritt vergessen werden (kein Macro, das ihn automatisch
  einschließt).

### Drift-3: git-Commit-Message ohne Template

- `git commit -m 'fix: update main logic'` — kein Conventional-Commit-Template, kein Multi-Line HEREDOC.
- Jeder Agent wählt eigene commit-message-Syntax.

### Drift-4: Absoluter Pfad in jedem Tool-Call

- `/home/tholo/Scripts/lean-ctx/src/main.rs` wird in reformat_file hardcoded.
- Ohne gemeinsame ROOT-Variable: jeder Agent schreibt den Pfad unterschiedlich (absolut vs. relativ).
