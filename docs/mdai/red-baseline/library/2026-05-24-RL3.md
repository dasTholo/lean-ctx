## 4. Beobachtbare Drift-Pattern

### Drift-1: git -C <absolute-path> vs. keine -C Flag (vs. RL1/RL2)

- RL3 nutzt `git -C /home/tholo/Scripts/lean-ctx status` (absoluter Pfad im git-Flag).
- RL1/RL2 nutzen `git status` ohne `-C` (implizites cwd).
- Drei Agents, drei verschiedene Wege denselben git-Befehl zu schreiben.
- Ohne gemeinsame GIT_ROOT-Konvention: vollständige Inkonsistenz über Reports hinweg.

### Drift-2: mode="full" für alle ctx_read-Calls (identisch zu RL2)

- Tech-Lead sagte "keine Abstraktionen" → keine mode-Überlegung.
- Alle 3 Reads: `mode="full"` — auch für große Dateien wie src/lib.rs.
- Inkonsistent mit RL1 (das mode="map" für CHANGELOG verwendete).

### Drift-3: Prosa-Beschreibungen pro Tool-Call erhöhen LOC erheblich

- RL3: 54 LOC für 12 Tool-Calls (= 4.5 LOC/Call inkl. Prosa).
- RL2: 38 LOC für 12 Tool-Calls (= 3.2 LOC/Call, weniger Prosa).
- Gleiche Anzahl Tool-Calls, aber RL3 ist 42% größer durch Inline-Kommentare.
- Authority-Pressure → mehr Dokumentation des "Warum", nicht weniger.

### Drift-4: Commit-Messages variieren zwischen Agents (kein Template-Erzwingung)

- RL1: `git commit -m 'fix: update main logic'` (kein Scope)
- RL2: `git commit -m 'refactor: clean up lib'` (kein Scope)
- RL3: `git commit -m 'fix(main): correct entry point logic'` (mit Scope)
- Alle benutzen Conventional Commits zufällig, aber mit inkonsistenter Scope-Verwendung.

### Drift-5: Namespace-Mix nach wie vor vorhanden

- `mcp__lean-ctx__ctx_shell` für git-Befehle
- `mcp__jetbrains__reformat_file` für Reformat
- Kein Hinweis, wie diese zwei Namespaces koordiniert werden — jeder Agent notiert dies unterschiedlich.
